🌐 Foundations

Definition
Web Scraping

Automated extraction of data from websites by simulating HTTP requests or browser interactions. Unlike manual copy-paste, scrapers programmatically parse the HTML returned by a server and extract structured data.

  • Treats every web page as a data source
  • Useful when no API exists or the API is restricted
  • Output: structured datasets (CSV, JSON, database)
Definition
Web Crawling

Systematically following hyperlinks across the web to discover and index pages. A crawler (or spider) starts with a seed URL list, downloads pages, extracts links, and queues them for further visits.

  • Search engine indexers (Googlebot) are crawlers
  • Crawling discovers which pages exist; scraping extracts data from them
  • Scrapy combines both: crawl + scrape in one framework
Web Archive
CommonCrawl

An open, non-profit repository of web crawl data since 2008. It is one of the largest publicly available datasets on the internet and a primary source for training large language models.

  • 240 billion pages crawled; 70 billion unique URLs
  • 7 petabytes of raw data, stored in WARC/ARC format
  • GPT-3/4 training data includes filtered CommonCrawl subsets
  • Monthly crawls; freely downloadable from Amazon S3
Web Archive
Wayback Machine

The Internet Archive's service that stores historical snapshots of websites since 1996. It provides time-travel access to how any URL looked at a specific date.

  • 735 billion web pages archived
  • Useful for recovering deleted content, tracking content changes over time
  • Wayback API: https://archive.org/wayback/available?url=<url>&timestamp=<YYYYMMDD>
  • Returns the closest available snapshot URL in JSON
File Formats
WARC / ARC Format

Container file formats used by web archives to store raw HTTP request/response pairs alongside metadata.

  • ARC (Archive): Early format used by CommonCrawl; stores response content
  • WARC (Web ARChive): ISO standard successor; stores full request + response + metadata
  • Each WARC record has: type, target URI, date, content-type, block content
  • CommonCrawl distributes data as compressed WARC files
Architecture
Scraping vs Crawling

Often used interchangeably, but they represent different operations in the data collection pipeline.

  • Crawling: Navigate the web graph — follow links, discover pages
  • Scraping: Extract structured data from a specific page
  • A scrawler (scraper + crawler) does both: crawl a site's structure and scrape each page
  • Scrapy, Crawlee, and custom asyncio scripts are typical scrawler architectures

🏗 How Web Pages Work

Web Technology
HTML (Structure)

HyperText Markup Language defines the semantic structure of a page using nested elements. Every HTML page is a tree of tags that a browser parses into a DOM.

  • Tags: <div>, <p>, <table>, <span>, <a href>
  • Attributes encode metadata: class, id, data-*
  • Scrapers primarily target HTML — it carries the visible text content
Web Technology
CSS (Presentation)

Cascading Style Sheets control visual styling. For scrapers, CSS is primarily useful as a selector syntax to target specific elements.

  • .class-name — selects by class attribute
  • #id — selects by unique ID
  • div > p — direct child combinator
  • a[href] — attribute presence selector
Web Technology
JavaScript (Behavior)

JavaScript executes in the browser to add interactivity and dynamically modify the DOM after page load. This creates a core challenge for scraping.

  • AJAX loads data asynchronously without page reload
  • SPAs (React, Vue, Angular) render content entirely via JS — the initial HTML may be empty
  • requests + BeautifulSoup only sees the initial HTML, not JS-rendered content
  • Selenium/Playwright execute JavaScript like a real browser
Core Concept
DOM — Document Object Model

An in-memory, tree-structured representation of an HTML document. The browser constructs the DOM from parsed HTML; JavaScript and scrapers both interact with it.

  • Element nodes: represent HTML tags (<table>, <td>)
  • Text nodes: the visible text inside an element
  • Attribute nodes: key-value pairs on elements (class="price")
  • BeautifulSoup replicates a subset of the DOM in Python
HTTP Protocol
HTTP Request & Response

The stateless protocol underlying all web communication. A scraper must correctly simulate browser requests to avoid being blocked.

  • GET: retrieve a resource; most scraping uses GET
  • 200: success   301/302: redirect   403: forbidden   404: not found   429: rate limited
  • User-Agent header: identifies the client — servers may block non-browser UAs
  • Cookies / Sessions: required for authenticated scraping
Selector Syntax
CSS Selectors vs XPath

Two primary languages for locating nodes within the DOM, both supported by BeautifulSoup and Scrapy.

  • CSS: concise, readable — span.price, div > ul > li
  • XPath: powerful, can traverse upwards — //td[@class='price']/text()
  • XPath can select text nodes directly; CSS cannot
  • Scrapy uses CSS for most cases; XPath for complex traversals

🐍 Python Scraping Tools

Library

BeautifulSoup (bs4)

An HTML/XML parsing library that creates a parse tree from raw markup. It does not make HTTP requests — it only parses the HTML you give it. Always paired with requests for static sites.

find() / find_all() Search by tag name, attributes, or CSS class. Returns a Tag object or list of Tags.
select() / select_one() CSS selector interface. soup.select('div.article > h2') returns a list of matching elements.
.get_text() Extracts visible text content from a tag and all its descendants, stripped of HTML markup.
.attrs / ['href'] Access element attributes as a dictionary. tag['href'] extracts hyperlink URLs.
Python — BeautifulSoup
import requests
from bs4 import BeautifulSoup

# Fetch the page (simulating a browser UA)
response = requests.get("https://example.com/products",
    headers={"User-Agent": "Mozilla/5.0"})

# Parse the HTML
soup = BeautifulSoup(response.text, 'html.parser')

# Extract all headlines with class 'product-title'
items = soup.find_all('span', class_='product-title')
data = [item.get_text(strip=True) for item in items]

# CSS selector alternative
prices = [tag.text for tag in soup.select('div.price > span')]
Use BeautifulSoup when:

You need a quick, one-off scrape of a static page. For recurring or large-scale jobs, prefer Scrapy's built-in concurrency and pipeline system.

Python — Scrapy Spider
import scrapy

class BlogSpider(scrapy.Spider):
    name = 'blogspider'
    start_urls = ['https://example-blog.com/']

    def parse(self, response):
        # Extract data from current page
        for title in response.css('.post-title'):
            yield {'title': title.css('::text').get()}

        # Follow pagination links
        for next_page in response.css('a.next'):
            yield response.follow(next_page, self.parse)
Asynchronous by default Twisted event loop enables concurrent downloads without threads. Easily configurable request rate (DOWNLOAD_DELAY setting).
CrawlSpider + Rules Built-in crawler that follows links matching regex rules. No manual link-following code needed.
Middlewares Hook points for proxy rotation, cookie management, User-Agent randomization, retry logic.
Item Pipelines Post-processing chain: validate data, write to CSV/JSON/database, deduplicate by URL hash.
Custom Tool

Scrawler (Custom Scraper + Crawler)

A self-coded scraper-crawler built with Python asyncio and multithreading. Designed for domain-bounded crawling with controlled depth, useful when Scrapy's overhead is undesirable or fine-grained control is needed.

Architecture
asyncio + Multithreading

Uses Python's asyncio event loop for I/O-bound HTTP requests combined with a thread pool for CPU-bound parsing. Achieves parallelism without spawning processes.

Constraints
50 Pages / Domain

Caps crawl depth per domain to avoid overwhelming servers and to stay within legal/ethical bounds. Configurable via a max_pages parameter.

Depth Control
3 Inner Levels

Only follows links up to 3 hops from the seed URL. Prevents crawl explosion while capturing most relevant content in a typical site hierarchy: homepage → category → article.

🤖 Browser Automation

Why browser automation for scraping?

JavaScript-rendered sites cannot be scraped with HTTP libraries alone. Browser automation tools launch a real (or headless) browser that executes JavaScript, waits for DOM updates, and allows interaction — exactly as a human would.

Library

Selenium WebDriver

Originally designed for automated browser testing, Selenium drives a real browser through a WebDriver protocol. It supports Chrome (ChromeDriver), Firefox (GeckoDriver), and others. For scraping, it's the go-to for small-scale JavaScript-heavy sites.

Python — Selenium
from selenium import webdriver
from selenium.webdriver.common.by import By

driver = webdriver.Chrome() # launches Chrome
driver.get("https://example.com")

# Accept cookie banner by XPath
driver.find_element(By.XPATH, '//button[@id="accept-btn"]').click()

# Extract all elements with a CSS class
elements = driver.find_elements(By.CLASS_NAME, 'product-title')
data = [el.text for el in elements]

driver.quit() # always close the browser
WebDriver Protocol JSON Wire Protocol over HTTP between Python and the browser. Each command is an HTTP POST to ChromeDriver or GeckoDriver.
Headless Mode Run Chrome/Firefox without a visible window: options.add_argument('--headless'). Faster and suitable for server environments.
Explicit Waits WebDriverWait + expected_conditions pauses execution until a specific DOM state is reached, avoiding flaky timing hacks.
Limitations No built-in concurrency; slower than Playwright; requires matching browser + driver versions; heavier resource footprint.
Library

Microsoft Playwright

Playwright uses a WebSocket connection to the browser's DevTools Protocol, making it significantly faster than Selenium's HTTP-based WebDriver. It supports Chromium, Firefox, and WebKit (Safari engine) with a single unified API.

Python — Playwright (sync)
from playwright.sync_api import sync_playwright

with sync_playwright() as p:
    browser = p.chromium.launch(headless=True)
    page = browser.new_page()
    page.goto("https://example.com")

    # Auto-wait until element is visible
    page.wait_for_selector('.product-list')

    # Extract data
    titles = page.query_selector_all('.product-title')
    data = [t.inner_text() for t in titles]

    # Intercept network requests
    page.on("response", lambda r: print(r.url))
    browser.close()
Auto-wait Playwright automatically waits for elements to be actionable before clicking or extracting. No manual sleep() or WebDriverWait boilerplate.
Network Interception Intercept/mock network requests with page.route(). Useful for blocking ads, capturing API responses, or injecting test data.
Async Support Full async/await API for concurrent page scraping within a single process — much faster than sequential Selenium.
Multi-browser Test/scrape across Chromium, Firefox, WebKit from one API. Browsers bundled — no driver version matching required.
Framework

Crawlee

A production-grade scraping framework from the Apify team, originally built for Node.js and now available for Python. It wraps Playwright with features specifically designed to avoid bot detection and handle enterprise-scale crawling.

Proxy Rotation Built-in proxy pool management. Automatically rotates IPs to avoid rate limiting and IP bans.
Anti-bot Fingerprinting Randomizes browser fingerprints (screen size, timezone, language, WebGL) to evade bot detection systems like DataDome or Cloudflare.
Persistent Request Queue Scraping state survives crashes. Resume crawls from where they left off without re-visiting already-scraped URLs.
Playwright Integration Uses Playwright as its browser backend, inheriting auto-wait, network interception, and multi-browser support.

Tool Selection Guide

Large-scale Python crawl → Scrapy — battle-tested framework with async engine, pipelines, and extensive middleware ecosystem.
Modern JS-heavy sites → Playwright — faster than Selenium, auto-wait, async support, multi-browser in one library.
Production + proxies + anti-bot → Crawlee — built for production resilience; persistent queues, fingerprint evasion, proxy rotation.
Quick static scrape → requests + BeautifulSoup — zero overhead, beginner-friendly, sufficient for one-time jobs.
Enterprise / managed service → Apify, Zyte (formerly Scrapy Cloud), ScrapingBee, BrightData — managed infra with CAPTCHA solving.
Large existing test suite → Selenium — if the team already has Selenium test infrastructure, leverage it for scraping too.

⚖️ Legal & Ethical Considerations

Protocol
robots.txt

The Robots Exclusion Protocol — a plain-text file at https://domain.com/robots.txt that specifies which parts of the site crawlers should not access.

  • User-agent: * — applies to all crawlers
  • Disallow: /admin/ — block access to path
  • Allow: /public/ — explicitly permit a sub-path of a blocked parent
  • Not technically enforced — a server cannot prevent access — but violations are unethical and may expose legal liability
Legal
Terms of Service (ToS)

Website ToS documents often explicitly prohibit automated access or scraping. Violating ToS can result in account bans, IP blocking, or legal action.

  • HiQ Labs v. LinkedIn (2019): US 9th Circuit ruled that scraping publicly accessible data does not violate the CFAA (Computer Fraud and Abuse Act)
  • Copyright may still apply to scraped content
  • GDPR implications if scraping personal data of EU citizens
Best Practice
Rate Limiting

Sending too many requests too quickly constitutes a denial-of-service attack from the server's perspective. Ethical scraping includes deliberate throttling.

  • time.sleep(2) between requests as a minimum courtesy
  • Scrapy's DOWNLOAD_DELAY setting and AUTOTHROTTLE extension
  • Schedule scraping during off-peak hours (nighttime for the target's timezone)
  • Respect Retry-After header on 429 responses
Best Practice
Identify Yourself

Setting a descriptive User-Agent that includes contact information is considered good practice — it allows site owners to reach you if issues arise.

  • Example: MyResearchBot/1.0 (contact: researcher@university.edu)
  • Contrast with mimicking a browser UA to evade detection — ethically different

robots.txt — Annotated Example

# Applies to all crawlers User-agent: * # Block crawler access to these sensitive paths Disallow: /basket Disallow: /checkout Disallow: /settings Disallow: /newsletter # Allow crawlers to access these sub-paths of blocked parents Allow: /newsletter-archive Allow: /settings-public # Sitemap location Sitemap: https://example.com/sitemap.xml
Ethical checklist before scraping:

1. Check robots.txt — does it disallow your target path?   2. Review the Terms of Service for explicit scraping prohibitions.   3. Will the data contain personal information (GDPR scope)?   4. Is there a public API that makes scraping unnecessary?   5. Set a respectful rate limit — not more than 1 request / 2 seconds for a typical site.

💡 Key Concepts

Architecture
Headless vs Headed Browser

A headed browser renders a visible window; a headless browser runs entirely in memory without a display. Headless is standard for server-side scraping.

  • Playwright: launch(headless=True) (default)
  • Headed mode is useful for debugging — you see exactly what the scraper sees
  • Some anti-bot systems detect headless mode via browser APIs — Crawlee randomizes these
Technique
Session & Cookie Management

Many sites require authentication or session cookies to serve content. Scrapers must handle login flows and persist cookies across requests.

  • requests.Session() automatically handles cookies and connection pooling
  • Selenium/Playwright: browser stores cookies naturally; use storage_state in Playwright to save/restore auth
Technique
Pagination Handling

Multi-page data sources require following pagination links or constructing URL patterns.

  • URL pattern: ?page=1, ?page=2 → iterate with a loop
  • Next-page link: soup.find('a', class_='next') → follow and recurse
  • Infinite scroll: AJAX loads more items — use Playwright to scroll and wait for new content
Infrastructure
Proxy Rotation

Using a pool of IP addresses to distribute requests and avoid IP-level rate limits or bans. Each request appears to originate from a different IP.

  • Residential proxies: harder to detect, more expensive
  • Datacenter proxies: cheap, often blocked by major sites
  • Crawlee, Scrapy middleware, BrightData all support proxy rotation
Architecture
Seed URL & Frontier

The seed URL(s) are the starting points for a crawler. The frontier (or request queue) holds URLs yet to be visited.

  • Scrapy: start_urls list → scheduler queues them
  • Crawlee: persistent RequestQueue — survives process restarts
  • URL normalization prevents duplicate visits to the same resource via different paths
Architecture
Politeness & Crawl Budget

Being a "polite" crawler means respecting the server's capacity. Crawl budget is the number of pages a crawler will visit on a given domain within a time window.

  • Scrapy: DOWNLOAD_DELAY + AUTOTHROTTLE_ENABLED
  • Stagger requests using jitter: random.uniform(1, 3) seconds
  • Crawling at night reduces server load impact

📖 Quick Glossary

Glossary
AJAX

Asynchronous JavaScript and XML. A technique for updating parts of a web page by making background HTTP requests without a full page reload. The main reason requests-only scrapers miss content on modern sites.

Glossary
SPA — Single Page Application

A web application that loads a single HTML page and dynamically rewrites content using JavaScript (React, Vue, Angular). The initial HTML often contains little more than a <div id="root"></div>.

Glossary
WebDriver

The W3C-standardized protocol for programmatically controlling a browser. Selenium communicates to ChromeDriver or GeckoDriver over HTTP using this protocol.

Glossary
DevTools Protocol (CDP)

Chrome's native protocol for debugger tools, used by Playwright (and internally by Puppeteer) via a persistent WebSocket. Faster than the WebDriver JSON Wire Protocol.

Glossary
Twisted

An event-driven networking engine for Python. Scrapy's underlying concurrency model — it handles many HTTP connections simultaneously via an event loop without blocking threads.

Glossary
XPath

XML Path Language. A query language for selecting nodes from an XML/HTML document. More expressive than CSS selectors — can traverse parent nodes and select text directly. Example: //div[@class='item']/h2/text()

Glossary
User-Agent

An HTTP request header identifying the client application. Browser UAs look like: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 .... Setting this in scraper headers reduces the likelihood of being identified as a bot.

Glossary
Rate Limiting (HTTP 429)

Server-side protection that returns HTTP status 429 Too Many Requests when a client exceeds an allowed request rate. Usually accompanied by a Retry-After header indicating how long to wait.

Glossary
Item Pipeline (Scrapy)

A sequence of processing steps applied to every item yielded by a Scrapy spider. Each pipeline component can filter, validate, transform, or persist the item — e.g., write to PostgreSQL or deduplicate by URL hash.

Glossary
Bot Detection

Server-side systems that identify and block automated clients. Common signals: too-fast request cadence, missing browser headers, predictable user behavior, shared datacenter IP ranges, headless browser API leakage (e.g., navigator.webdriver === true).

Glossary
Splash

A lightweight JavaScript rendering service designed for use with Scrapy. Acts as a headless browser accessible over HTTP — Scrapy sends a URL, Splash returns rendered HTML. Less capable than Playwright but integrates natively with Scrapy.

Glossary
CFAA

Computer Fraud and Abuse Act — US federal law governing unauthorized computer access. The 2019 HiQ v. LinkedIn ruling established that scraping publicly available data does not violate the CFAA, though the legal landscape continues to evolve.

Phase 2 — Scrape the Static Version with BeautifulSoup
Slides 13–14 · requests + bs4 + multi-page pagination

Create ~/web-scraping-lab/phase2_static.py. This scraper automatically follows all 10 pages.

phase2_static.py — BeautifulSoup
import requests
from bs4 import BeautifulSoup
import time

BASE_URL = "http://quotes.toscrape.com"
all_quotes = []
page_url = BASE_URL

while page_url:
    resp = requests.get(page_url, headers={"User-Agent": "SRH-Lab-Bot/1.0"})
    if resp.status_code != 200:
        print(f"Error {resp.status_code} — stopping"); break

    soup = BeautifulSoup(resp.text, "html.parser")

    for block in soup.find_all("div", class_="quote"):
        text = block.find("span", class_="text").get_text(strip=True)
        author = block.find("small", class_="author").get_text(strip=True)
        tags = [t.get_text(strip=True) for t in block.find_all("a", class_="tag")]
        all_quotes.append({"quote": text, "author": author, "tags": ", ".join(tags)})

    nxt = soup.find("li", class_="next")
    page_url = BASE_URL + nxt.find("a")["href"] if nxt else None
    time.sleep(1) # polite rate limit — Slide 29

print(f"Collected {len(all_quotes)} quotes")
print(all_quotes[0])

Why zero?

The /js/ page delivers an empty <div id="quotes"></div>. A JavaScript file fills it after the browser executes it. The requests library never runs JavaScript — it only fetches the initial HTML. This is precisely the problem described on slides 18–19, and why we need Playwright in Phase 4.

Phase 4 — Scrape the Dynamic Version with Playwright
Slides 22–23 · Headless Chromium + auto-wait

Playwright launches a real Chromium browser, waits for JavaScript to populate the DOM, then extracts data with the same CSS selectors. Create phase4_dynamic.py:

phase4_dynamic.py — Playwright (single page)
from playwright.sync_api import sync_playwright

all_quotes = []

with sync_playwright() as p:
    # headless=True → no visible window (best practice, Slide 23)
    browser = p.chromium.launch(headless=True)
    page = browser.new_page()
    page.goto("http://quotes.toscrape.com/js/")

    # Auto-wait until at least one quote block appears in the DOM
    # Playwright handles this natively — no time.sleep() needed here
    page.wait_for_selector("div.quote")

    for block in page.query_selector_all("div.quote"):
        text = block.query_selector("span.text").inner_text()
        author = block.query_selector("small.author").inner_text()
        tags = [t.inner_text() for t in block.query_selector_all("a.tag")]
        all_quotes.append({"quote": text, "author": author, "tags": ", ".join(tags)})

    browser.close()

print(f"Quotes found: {len(all_quotes)}") # 10 — first page only
print(all_quotes[0])

Phase 5 — Handle Pagination on a Dynamic Site
Key concept: click the Next button and wait for new content to load

On a dynamic site there is no raw href to follow. You must programmatically click the Next button and wait for the DOM to update. Create phase5_paginated.py:

phase5_paginated.py — Playwright + pagination
from playwright.sync_api import sync_playwright
import time

all_quotes = []

with sync_playwright() as p:
    browser = p.chromium.launch(headless=True)
    page = browser.new_page()
    page.goto("http://quotes.toscrape.com/js/")
    page.wait_for_selector("div.quote")
    page_num = 1

    while True:
        print(f"Scraping page {page_num}...")
        for block in page.query_selector_all("div.quote"):
            all_quotes.append({
                "page": page_num,
                "quote": block.query_selector("span.text").inner_text(),
                "author": block.query_selector("small.author").inner_text(),
                "tags": ", ".join(t.inner_text() for t in block.query_selector_all("a.tag"))
            })
        next_btn = page.query_selector("li.next > a")
        if not next_btn:
            print("No more pages."); break
        next_btn.click()
        page.wait_for_selector("div.quote") # wait for new quotes
        time.sleep(1) # polite pause — Slide 29
        page_num += 1
    browser.close()

print(f"\nTotal quotes: {len(all_quotes)}")
